# Data dictionary and provenance

> Earlier source-specific examples below may describe the superseded workbook. See [Final source and flow](FINAL_SOURCE_AND_FLOW.md) for the active final workbook and evidence limitations.

## Active source

The active fictional POC source is `data/private/FORGE_60_Opportunities_26_Column_Agent_Input.xlsx`, copied byte for byte from the supplied workbook. It is excluded from Git. `Opportunity_Input` contains 60 unique `FORGE-...` IDs, 26 columns, six practices with ten cases each, and source stages Identified 18, Noticed 22, Qualified 14, and Validated 6. The source sales stage is separate from FORGE review status.

The workbook also contains `Contracts` (60 rows), `FinOps_Evidence` (54), `Existing_Opportunities` (11), `SME_Directory` (12), `_Lists`, `Field_Dictionary`, and `Read_Me`. The embedded 12-person SME tab is validated but no longer used for recommendations. The active specialist source is `data/private/Kyndryl_Synthetic_SME_Directory_60.csv`, with 60 people and ten per practice. The importer checks exact column names, required values, row counts, uniqueness, money and dates, and cross-sheet keys. Six missing evidence IDs are intentional. See [workbook validation](UPDATED_WORKBOOK_VALIDATION.md) and [SME validation](SME_DIRECTORY_VALIDATION.md).

`data/private/opportunity_details.csv` contains the full 60-row, 26-column opportunity view. Its IDs, headers, and cell values match the active workbook. The tracked `data/opportunity_summary.csv` is generated by `scripts/build_summary.py`; it contains six practice-level aggregate rows only. The client dashboard reads aggregate API metrics and exposes no source rows. The workbook remains the active import source.

## Main API fields

| Field | Source and meaning |
| --- | --- |
| `opportunity_id`, `opportunity_name` | `Opp No`, `Opp Name` in `Opportunity_Input`. |
| `practice`, `source_sales_stage` | `Practices`, `S/S Name`; neither is a FORGE approval. |
| `customer_name`, `customer_number`, `industry`, `source_owner_user_name` | Source intake fields, private to the internal workflow. |
| `source_created_at`, `source_file`, `source_sheet`, `source_row`, `source_record_id`, `ingested_at` | Source date and import provenance. |
| `environment`, `business_service`, `criticality`, `rto_minutes`, `rpo_minutes`, `technical_constraints` | Source context used for POC assessment. |
| `source_baseline_monthly_cost`, `source_proposed_monthly_cost`, `source_implementation_cost` | Source USD cost inputs; these are synthetic, not actual customer telemetry. |
| `contract` | Joined contract ID and optimization scope. Excluded optimization types block approval. |
| `evidence` | Joined observed baseline and period; missing or stale evidence blocks approval. `verified=True` means only that synthetic references agree. |
| `pipeline_matches` | Exact active matches on customer number, asset group, and optimization type. Closed reference rows do not block. |
| `smes` | Fictional CSV candidates matched by an explicit optimization-to-specialization map, practice, and service type. Each carries a match reason and availability. |
| `assessment`, `review_status`, `case_version` | Calculated policy result, independent human-review state, and content version used to prevent stale approval. |
